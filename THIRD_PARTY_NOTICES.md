## Linear-regression implementation

The earlier exercise compared normal-equation least squares, mini-batch
gradient descent, and stochastic gradient descent. The Python module keeps
that mathematical comparison, using NumPy `lstsq`, a shared batch-update loop,
and a separate training-only scaler and held-out evaluation. These are
standard least-squares methods, not algorithms invented by this project.

## Decision-tree example

The decision-tree module generates its own categorical combinations and labels
in `make_demo_data()`. The labeling rule is explicitly invented for this
repository. It does not redistribute an external dataset. The saved example
tables, predictions, and diagrams are generated from that synthetic data.

The implementation illustrates ID3, described by J. R. Quinlan in
[Induction of decision trees](https://doi.org/10.1007/BF00116251) (1986).
The earlier local version used global arrays and explicit node indices. The
Python version uses recursive dictionaries, majority-label fallbacks, and
optional depth limits. The paper is a method reference; its text and figures
are not distributed here.

## HOG and SVM example

The image-classification module draws its own grayscale silhouettes in
`make_demo_images()`. Its public notebook and saved image illustrations use
only these generated examples. No external vehicle photographs are bundled.

The HOG feature implementation follows the method described in:

- Navneet Dalal and Bill Triggs, [Histograms of Oriented Gradients for Human
  Detection](https://lear.inrialpes.fr/people/triggs/pubs/Dalal-cvpr05.pdf), 2005.

SVM training and prediction use the separately installed scikit-learn
[`SVC`](https://scikit-learn.org/stable/modules/generated/sklearn.svm.SVC.html),
which uses LIBSVM. This repository supplies the feature extraction and
experiment pipeline, not the SVM solver. Scikit-learn and its bundled components
retain their upstream licenses; their source is not vendored here.

### SVM implementation history

The earlier local materials included `svmTrain.m`, attributed by their
accompanying example notes to Andrew Ng's machine-learning course, and
`bitjoy_seqminopt.m`, corresponding to bitJoy's
[SMO explanation and MATLAB implementation](https://bitjoy.net/posts/2016-05-02-svm-smo-algorithm/)
(2016). The earlier linear and Gaussian solvers closely follow the
`svmTrain.m` example. These are relevant antecedents, not evidence of a
permissive license: redistribution and adaptation permission for these local
reference copies has not been verified. Neither reference implementation is
bundled or offered under this repository's MIT License.

An earlier revision of this repository contained a handwritten Python SMO
solver developed after reviewing those local materials. To avoid relying on
that unresolved adaptation history, the current version removes the handwritten
solver and its optimization outputs and calls scikit-learn `SVC` directly.
No pair-update implementation from that solver remains in the current source.
This change does not itself remove older Git snapshots or resolve permission
for their contents. Those earlier versions are not certified as legally
cleared; a citation or this project's MIT License does not supply missing
third-party permission.

The earlier image pipeline called MATLAB's `extractHOGFeatures`; it did not
include that function's source. The Python HOG descriptor uses NumPy gradient
and histogram operations and is a simplified variant, as documented in the
module README. Paper text, paper figures, and the earlier MATLAB source files
are not distributed here.

The optional loader reads separately supplied local images. Their source terms
continue to apply; this repository's MIT License does not grant image rights.
The default export for local runs is Git-ignored and contains no source images.

## Handwritten-digit example

### Network implementation history

The earlier local prototype followed MathWorks' example,
[Create Simple Deep Learning Neural Network for Classification](https://www.mathworks.com/help/deeplearning/ug/create-simple-deep-learning-network-for-classification.html).
The experiment themes (activation functions, batch normalization, learning
rates, and a small CNN) carry over from that prototype. The Python version
expresses the networks and training loop with PyTorch and uses a different
dataset and train/validation/test evaluation. The linked tutorial identifies
this background, not permission to redistribute MathWorks source material.
MathWorks example source files, documentation text, figures, pretrained
weights, and example digit images are not bundled here.

The CNN's 6/16 convolution channels and 120/84-unit dense layers follow the
LeNet architectural family described by LeCun, Bottou, Bengio, and Haffner in
[Gradient Based Learning Applied to Document Recognition](https://bottou.org/papers/lecun-98h)
(1998). The use of ReLU, max pooling, batch normalization, and 28 × 28 inputs
makes this a LeNet-style model, not an exact reproduction of LeNet-5.

### Dataset

The neural-network module uses scikit-learn's `load_digits` copy of a subset
of the UCI Optical Recognition of Handwritten Digits dataset:

Alpaydin, E. and Kaynak, C. (1998). *Optical Recognition of Handwritten Digits*
[Dataset]. UCI Machine Learning Repository. https://doi.org/10.24432/C50P49.

The [UCI source page](https://doi.org/10.24432/C50P49) lists the dataset under
[Creative Commons Attribution 4.0 International](https://creativecommons.org/licenses/by/4.0/).
The repository's MIT License does not replace that dataset license.

The source 8 × 8 images are divided by 16 and bilinearly resized to 28 × 28
for the experiment. The module creates its own stratified train/validation/test
split of the library-supplied subset. These changes are preprocessing for the
experiment; the data is not MNIST. Raw dataset files remain in the separately
installed scikit-learn package. The public notebook and saved figures contain
aggregate results, not copies of input digit images or pixel arrays.

## Vehicle detection: YOLOv3

### Licensed Python reference

The decoding, target assignment, and loss in `object_detection/yolo.py` are
adapted from `src/model.py` and `src/training.py` in Western Digital's
[YOLOv3-in-PyTorch](https://github.com/westerndigitalcorporation/YOLOv3-in-PyTorch),
revision `5944f2eae2b8e1e64c7c50cd42aa5e97e9d0e98c` (release branch).
That revision provides a
[BSD-3-Clause license](https://github.com/westerndigitalcorporation/YOLOv3-in-PyTorch/blob/5944f2eae2b8e1e64c7c50cd42aa5e97e9d0e98c/LICENSE),
copyright 2019 Western Digital Corporation or its affiliates.
The full notice is retained in the adapted file and in
[the bundled license](LICENSES/western-digital-yolov3-BSD-3-Clause.txt).
`object_detection/yolo.py`, including its modifications here, is distributed
under BSD-3-Clause; the root MIT license does not replace it. The reference
was chosen for its explicit source license, not merely its repository name.

Changes include two detection scales instead of three, one vehicle class,
dynamic grid strides for 227-pixel inputs, a sigmoid-space center loss,
decoded pixel boxes for the background ignore mask, empty-target handling,
and calls to torchvision for IoU and NMS. This is a small adaptation, not a
copy of the upstream training application. Upstream photos, datasets, fonts,
checkpoints, and pretrained weights are not bundled or downloaded by this code.

The method reference is Redmon and Farhadi,
[YOLOv3: An Incremental Improvement](https://arxiv.org/abs/1804.02767) (2018).
The backbone is the separately installed torchvision
[`squeezenet1_1`](https://docs.pytorch.org/vision/stable/models/generated/torchvision.models.squeezenet1_1.html)
with `weights=None`. This project supplies the two-head architecture and
experiment pipeline; it does not claim to have invented YOLOv3 or SqueezeNet.

## SMS text classification

### Code and earlier example

The earlier local MATLAB exercise followed MathWorks'
[Classify Text Data Using Deep Learning](https://www.mathworks.com/help/deeplearning/ug/classify-text-data-using-deep-learning.html)
and its sequence-model examples. Word embeddings, LSTM/BiLSTM comparison,
learning-rate changes, and dense-head changes carry over as experiment themes.
The earlier examples were reviewed to understand the task; no separate
permissive source license was established for those local copies.

This module uses the separately installed PyTorch
[`nn.LSTM`](https://docs.pytorch.org/docs/stable/generated/torch.nn.LSTM.html)
and `nn.Embedding` implementations, with this project's preprocessing,
architecture definitions, training loop, and evaluation. It does not copy the
MATLAB helpers or vendor a third-party Python tutorial. Scikit-learn supplies
the TF-IDF and naive Bayes baseline. These libraries retain their own licenses;
the new module's own contributions use the root MIT license. This is an
implementation-history statement, not a clean-room claim or a license to
redistribute MathWorks text, source files, or figures.

### Dataset and version choice

Almeida, T. & Hidalgo, J. (2011). *SMS Spam Collection* [Dataset].
UCI Machine Learning Repository. https://doi.org/10.24432/C5CC84.

The [official UCI page](https://archive.ics.uci.edu/dataset/228/sms+spam+collection)
lists [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/) as the dataset
license (checked 2026-11-14). It is separate from the source-code MIT license.
The downloader uses UCI's official archive, verifies the message-file SHA-256,
and retains its original readme locally. That older readme identifies Almeida
and Gomez Hidalgo as copyright holders and includes disclaimer/liability terms;
it is not replaced or relabeled as MIT.

The earlier local `spam.csv` has 5,572 rows and extra CSV columns. It overlaps
substantially with the official 5,574-row text corpus, but is not byte-identical,
and its exact redistribution source was not established. The accompanying
`FactoryReportsDatasetLicense.txt` applies to the separate factory-report data,
not to `spam.csv`. Neither that CSV nor the factory-report dataset is used or
distributed by this Python module. Retraining uses the official UCI version.

Processing changes are lowercase word/number tokenization, removal of normalized
exact duplicates, a stratified train/validation/test split, and training-only
feature fitting. Recurrent inputs retain the first 60 tokens and use padding;
the TF-IDF baseline uses full normalized messages. These choices and the changed
data version mean scores are not directly comparable to the earlier exercise.

The local corpus can contain phone numbers, URLs, and personal text. The public
module exports aggregate metrics, confusion counts, and plots only. Raw messages,
the source CSV/archive/readme, learned vocabulary, word clouds, individual
predictions, and trained weights are not included. This limits redistribution;
it is not a claim that a data license grants every possible privacy or other
right. The dataset attribution and license link remain even though raw records
are not bundled. No author or institution endorses this project.

## Software dependencies

The code imports NumPy, pandas, Matplotlib, scikit-learn, and Pillow; the neural
and text modules additionally use the optional PyTorch dependency. Vehicle detection
also uses torchvision and SciPy, installed separately. Jupyter/IPython
provides the notebook environment, and pytest provides the test runner.
Dependencies are declared in `pyproject.toml` and the tested environment is
recorded in `requirements-lock.txt`.

These packages are installed separately rather than copied into this
repository. Their respective upstream licenses continue to apply.
